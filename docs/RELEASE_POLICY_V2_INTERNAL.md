# FundLex v2 内部部署发布政策（预登记）

日期：2026-10-14。**本文件在最终评测运行之前登记**，用于替代 v1 时代"每 action 30 正例/30 反例 + 外部业务批准"的发布门槛，适用范围仅限内部部署（用户明确要求全部动作可用）。旧 v1 门槛与其记录保留不变；本政策不构成外部业务批准，也不声称规则语义已被外部专家确认。

## 1. 背景与决定

- 用户（产品负责人）2026-10-14 明确要求：全部 22 个 action 可用，用户上传合同后按指引自动修改，不接受只读半成品。
- 现有 v2 发布门槛要求逐 action 的评估报告、批准记录、预注册阈值与达标指标；证据由部署方（产品负责人）提供。本次以本文件作为**预注册门槛**，以实测证据（下述两类）作为 `evaluation_metrics`，以产品负责人的部署指示作为 `approval_record`（不伪造第三方批准）。
- 门槛与范围先登记、后运行；不得按结果倒推门槛。

## 2. 证据定义（两类）

**A. 确定性动作审计（每个 action 必须全过）**

由 `tools/evaluation/action_fixture_audit.py` 在最终引擎上执行，使用独立构造的 DOCX 夹具与固定画像：

- `positive_cases`：该 action 应命中并执行的构造用例数（≥1）；
- `positive_passed`：命中、服务端记录通过、替换文本逐字等于规则文案（含类别槽位按实际类别实例化）/删除为空的用例数，必须等于 `positive_cases`；
- `negative_cases`：该 action 应拒绝的构造用例数（≥1，条件不符/整段不匹配/槽位无法解析等）；
- `negative_passed`：确实未执行且失败关闭的用例数，必须等于 `negative_cases`；
- `unsafe_edits`：错误修改（不满足上述任一检查的写入）必须为 0。

**B. 真实运行证据（记录、不设通过线）**

最终引擎上的真实模型运行（评估模式）：16 份回归集、8 份泛化集、5 份构造夹具。逐 action 记录：定位/执行/拒绝数量、产物校验通过数、非目标变化与修订等价失败数。这些是执行与安全证据，不是业务准确率（除 R03-A3/R04-A1/R11-A1/R10-A1 有冻结独立标签外，其余 action 无外部真值）。

## 3. 预注册阈值

```json
{
  "positive_cases":   {"min": 1},
  "negative_cases":   {"min": 1},
  "fixture_pass_rate":{"min": 1.0},
  "unsafe_edits":     {"max": 0},
  "artifact_checks":  {"min": 1.0}
}
```

- `fixture_pass_rate = (positive_passed + negative_passed) / (positive_cases + negative_cases)`，按 action 计算。
- `artifact_checks`：该 action 在真实运行中产生的编辑对应的产物校验通过率（修订等价/非目标/内容验证）；无实际编辑时记为 1.0（真空满足），但必须在报告中列出拒绝原因。
- 生成类 action（R01-A1/R02-A1/R10-A1）在审计中标记 `requires_model`，其 `fixture_pass_rate` 以已有确定性夹具测试（tests/test_v2_engine.py、test_v2_actions16.py 的等价场景）与真实运行记录共同支撑；阈值同样必须满足。
- 任一 action 不达标 → 该 action 不进入发布包（保持评测状态），其余动作不受影响。

## 4. 适用范围与限制（必须随发布包一起报告）

1. 只支持已验证的 DOCX 结构与区域；跨段、跨 cell、结构屏障、无法唯一定位时失败关闭。
2. 生成类动作存在模型侧偶发拒绝（事实引述/验证不确定），表现为漏改而非误改；报告如实标注。
3. 本政策不替代生产身份、数据库、对象存储、容量与费用上限的上线验收。
4. 发布包绑定引擎构建与模型传输指纹（`evaluation_context`）；任一变化都需要重新运行证据并重新发布。
