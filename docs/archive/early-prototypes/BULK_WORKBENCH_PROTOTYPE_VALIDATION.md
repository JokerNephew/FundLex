# 任务级 HTML 原型验证记录

日期：2026-10-13。验证对象：`workbench/prototypes/bulk-contract-workbench.html`。本阶段仅交付离线 HTML 原型，正式应用接入等待用户确认。

## 本轮产品调整

- 桌面左侧导航固定在顶部栏下方，工作区独立滚动；手机固定顶部导航，保留文字标签。
- 总览、处理进度、合同结果及示例汇总统一覆盖“四季度合同条款核验”任务全部 368 份示例合同。
- 用户流程移除底层批次、拆批数量、单批 20 份限制与 API 说明。技术约束与正式任务编排缺口仅保留在设计文档。
- 导入保持多文件、文件夹入口、拖放处理、追加、移除、清空、异常筛选、搜索与分页；追加/移除/清空取消旧模拟上传计时器。

## 实际浏览器验证

使用 Codex 内置浏览器加载本地静态页面，操作实际 DOM 和文件选择器。所有处理状态均为页面内示例；未调用真实 API 或模型。

| 场景 | 实测结果 |
| --- | --- |
| 初始任务规模与进度 | 总数 368，已上传 368，已处理 259，失败关闭 33，排队 68，处理中 8；292/368 进入终态，总进度 79%。各数量来自同一组示例记录。 |
| 固定侧栏 | 1440×900 下工作区滚动至 `scrollTop=662.4` 后，侧栏 top 仍为 64、bottom 仍为 900；不会随合同列表滚动。 |
| 暂停/继续 | 暂停整个任务后“推进示例一步”禁用；继续后可以推进，数量变为已处理 260、排队 67，终态 293/368。 |
| 完成状态 | 通过 76 次页面内示例推进到全部终态：已处理 335、失败关闭 33、排队与处理中均为 0，进度 100%；推进禁用。随后重载恢复初始示例。 |
| 任务全部合同查询 | 搜索 `_368.docx` 可定位任务最后一份合同；无底层批次选择器。 |
| 结果筛选 | 失败关闭 33 份、类型排除 25 份、结果不完整 36 份；“不完整 + 份额/收费证据不完整”组合匹配 17 份。资格与处理状态、交付状态独立呈现。 |
| 排序与分页 | 文件名 Z–A 排序可用；全部 368 份结果可进入第 2/37 页。 |
| 详情与键盘 | 打开长文件名合同 `_028.docx`，详情标题完整换行；不完整结论与不可认定直接使用均可见。Esc 关闭后焦点返回“查看证据”。 |
| 多文件选择 | 通过浏览器选择器选择两个构造 DOCX 和一个 TXT 元数据夹具，保留 3 条记录、2 个可接收、1 个格式异常。夹具无真实业务资料。 |
| 文件夹入口 | `webkitdirectory` 与 `multiple` 属性存在，文件夹选择器打开；选择上述夹具目录并等待异步文件枚举后，出现同样的 3 条记录。 |
| 数百份导入 | 载入 371 条内置示例：368 个可接收，3 个异常；异常筛选分别显示不支持格式、27 MiB 超限和文件名/大小相同的疑似重复。 |
| 上传与处理分离 | 模拟提交后显示“模拟上传完成 · 368/368”，处理阶段仍显示“模拟排队中 · 368 份；尚未处理”。模拟中清空清单后旧计时器未恢复“上传完成”。 |
| 示例下载 | 实际下载逐合同 JSON 报告与任务 Markdown 汇总；检查 JSON 保留中文原因、原始码且 `final_contract_available=false`；汇总合同总数为 368。不是后端产物。 |
| 视口 | 桌面 1440×900、笔记本 1280×800、手机 390×844。手机总览、导入、进度、结果四页 `documentElement.scrollWidth=390`，桌面/笔记本分别为 1440/1280，无页面级横向溢出；宽表仅在局部容器内滚动。 |
| 控制台与语法 | 浏览器页面 error 日志为空。抽取内联脚本后 `node --check` 退出码 0。 |

多文件拖放的事件处理已实现，未在本轮自动化中执行桌面跨窗口拖拽动作。文件检查仅用于原型元数据体验；实际 DOCX 包完整性仍必须由后端校验。

## 真实能力与剩余限制

原型展示的是任务层产品方案。现有真实后端仍以批次为单位提供接口；持久任务实体、任务整体控制、聚合查询、任务汇总与生产身份尚需正式实现，详见 `BULK_WORKBENCH_PROTOTYPE_DESIGN.md`。页面不会把这些示例操作宣称为现有 API 能力。

本阶段未执行真实 DOCX 上传到 worker、真实模型处理、生产身份或未授权结果隔离验收，也未重跑 230/514 份回归。页面没有生产登录或私有合同结果，全部数据为明确标注的示例。后端、规则、正式前端、模型开关和生产数据均未在本任务中修改；仓库中其他并行修改不纳入本次提交。
