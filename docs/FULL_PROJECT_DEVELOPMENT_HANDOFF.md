## 6. 目标模块与数据契约

以下模块和字段为目标设计，**当前不存在相同名称或接口的保证**。接续agent可调整命名，先形成可检查的schema并在前后端共用含义。

### 6.1 核心对象

| 对象 | 必需内容 |
| --- | --- |
| GuideVersion | id、owner、built_in/custom、文件名、source_sha、解析/schema/prompt版本、规则哈希、状态、来源位置、验证记录 |
| Rule | 稳定id、业务名称、来源原文与新文、授权操作、条件/依赖、槽位、必须保留及核验要求，不固定22条 |
| SourceDocument | 原件id/hash、版本、完整部件清单、读取缺口；原件不可变 |
| Block | 稳定id、part、顺序、物理地址、原文、表格坐标、可读/可写能力及原因 |
| BusinessScope | 模型识别的业务功能、block集合、跨段/跨章关联、正文摘要关系、未完成边界 |
| Fact | 类别/收费/渠道/期限/机制关系、明确/未知/冲突、证据地址与原文、版本 |
| Target | 稳定id、关联规则、对象条件与位置、原文span、理由、状态、依赖，不以引文字符串去重 |
| RevisionOperation | id、原件span或插入锚点、旧文、新文、规则来源、保留事项、关联目标与修订单元 |
| PlanVersion | 原件/指引/事实版本、操作集合、哈希、父版本及修改原因 |
| ArtifactVersion | plan版本、final/redline实际路径与hash、source↔artifact映射、技术校验记录 |
| AuditIssue | 规则/目标/位置、具体问题、实际证据、影响单元、建议、仲裁及解决状态 |
| ScanTask | 文档版本、窗口原文地址/token、已完成/未完成、分页cursor、上下文来源、调用记录 |

原件地址永久绑定原件，产物地址每轮独立。产物文本映射来源范围或generated_by操作id；不能将产物字符坐标直接用于原件。读实际文件验证映射。

映射记录source span/anchor、artifact span、operation_id、修订单元、映射类型与版本，覆盖保留、替换、插入、删除及一对多/多对一；部件与表格也包含。删除在产物无文本但保留来源与相邻锚点。映射不确定重新定位回查，禁止猜坐标。

每份合同维护workflow_epoch。事实更正、输入版本或影响范围变更使epoch递增，响应、计划、审计和提交均携带并比对；配置页切换不改变运行任务的指引快照。旧epoch尚未最终交付的候选文件不开放下载，已展示的中间结果明确失效。正式交付后若主动重跑产生新任务/结果版本，历史已交付文件保留可追溯，不静默篡改。

### 6.2 分开的状态维度

- 上传状态：待上传、接收、拒绝；与处理分开。
- 任务状态：queued/running/paused/retry_wait/completed/failed等，blocked按明确故障契约映射，不能无限重试假运行。
- 阶段：结构读取、事实理解、范围映射、目标盘点、规划、写入、复核、修复/仲裁、最终查漏、交付。
- 目标：pending/needs_edit/satisfied/not_applicable/modified_verified/unresolved/unsupported；每个有依据与位置。
- 交付：complete、incomplete、excluded、not_generated；blocked作为任务原因，不假装内容完整。评测运行独立标识，不与正式结果混名。
- 指引：uploaded/parsing/parsed/parse_failed/validated/released/archived；parsed与released明确不同。

既有状态如complete_with_exceptions需显式映射：存在应改未完成或未知时归incomplete；明确不适用和已满足不算未完成。旧报告保持engine/schema可识别，不强行套新完整口径。

DeliveryService统一裁决交付状态，前端、Worker和下载服务不能各自猜complete。依据绑定source/guide/epoch的规则处置、扫描账本、目标及实际产物审计；无目标规则也须有已搜索范围和satisfied/not_applicable/no_target_authorized证据，未知不算无目标获准结束。

## 7. 修订流水线与不可省略的细节

### A. 结构与事实

代码完整提取可读部件，读取和编辑能力分开；失败部件记录缺口。识别物理章/节/段落，目录条目不能冒充正文标题；歧义由模型核对，未分类内容保留。

模型从必要原文建立收费事实，不按类别字母或不存在信息猜否定。潜在资格排除独立核查；事实冲突补读证据并仲裁。

### B. 映射与目标盘点

代码提供结构、原文地址和指引。模型映射到业务子节，章只作导航。子节可跨标题或多个物理段落；标题不是业务准入白名单。

完整读子节，携带收费事实和摘要对应位置。超过容量按token拆分，跨界条款显式未完；输出多时分页继续，不能截断当完成。盘点所有目标，单规则多目标不构成歧义。

输出id/位置/引文/规则/理由；代码按位置回查。核心词不作硬否决，重复引文以地址区分。机械答复错误提供真实原文修复定位。

找不到、未知、已满足、不适用分别记录；缺失是否新增由指引授权决定。已有命中仍核对目标覆盖，不只对空结果补扫。

### C. 联合规划与文案

模型确定修改范围与保留事项，按业务依赖与物理重叠组织修订单元。销售服务费包含公式保留、支付替换、用途删除及新文，不能独立操作后产生冲突。

固定新文取自指引来源；槽位依据实际关系。指引允许的语义生成也附来源和事实。跨段文字优先保持原段落结构，多个精确操作构成一个单元；删段/合段另有验证能力。

正文摘要分别形成目标，关联语义一致，不要求相同数量或新文串完全相同。没有实际摘要目标且来源没有新增义务时不机械复制。

### D. 写入与实际复核

执行前核对原件、计划、旧文和地址，生成独立临时文件。验证包可读、原生修订、接受全部等价final、拒绝全部恢复source内容、未授权范围与结构保留；元数据差异需声明。

模型复核基于重新读取的final.docx，对要求、事实、余文、正文摘要和目标覆盖提供可定位证据。不能仅用计划replacement充当写入成功。

可复用的是未受影响方案，不是旧产物最终授权。事实/规则/关联条款变化失效相关适用性、目标、方案及审计；重大事实更正做影响发现，弥补未声明依赖。

重大收费画像更正重新核查全部规则适用性、映射及目标覆盖，完成影响闭包后才确认哪些单元可复用，不能仅沿已声明依赖检查。

### E. 重试与修复

技术临时故障退避、抖动及Retry-After；鉴权/余额/预算停止保留断点。次数和HTTP尝试分别计量，每次预留预算，账本不重置。

输出截断分页/拆块；地址错误重定位；业务问题补上下文、按具体反馈修复。有分歧仲裁读指引、原件、当前产物及双方证据，不按投票或置信度直接决定。

修复更新完整plan，代码从原件重生成。原文残留补目标，生成错误修原操作，缺失义务选来源锚点。独立正确单元保留，强依赖单元联合处理。迟到响应和旧Worker不能提交过期版本。

预算、余额、鉴权等可恢复停止进入paused并带明确blocked_reason，保存待办扫描、epoch、计划、轮次及账本；不自动标completed，也不自动无限重试。恢复后不重置账本或修复次数。业务修复上限耗尽或用户明确结束处理时才结算incomplete/not_generated，任务处理状态与交付完整性分别记录。

工作文件只采用来源、事实与计划仍有效、且对应实际文件已通过技术及所声明业务核验的修改。不把缺乏审计的候选文件冒称已核验工作稿；无可用已验证版本则只给报告并记not_generated。保留上一版已核验文件时明确其版本，不能称为最新失败计划产物；若重新生成子集，需验证该新组合，预算不足则待恢复，不猜测安全。

### F. 最终查漏与交付

## 10. 指引解析与发布的可用闭环

内置指引首次安装自动准备，正常用户不需先配置。指引JSON不可写死旧动作数、编号或槽位。

代码保留完整原文、编号、表格和颜色；模型拆来源组、区分原文/新文、条件/操作/变量/引用。独立核验先读来源形成期望要求，再对账解析结果；JSON合法不等于规则完整。

解析问题自动补读修复，不静默漏组。自定义版本展示状态，上传不自动切换。未完成解析不能成为正常任务的已验证指引。

定义实际可执行的版本验证/发布流程：来源覆盖、条件/槽位/操作合法性、结构化答复、专项业务夹具及独立真实合同证据；引擎/模型传输/提示与证据绑定。内置版本完成新引擎验证后发布；自定义不同规则需对应验证，不能伪造审批或直接改released=true。

首次发布采用独立qualification通道，由开发者或有权限的版本管理者启动，绑定候选guide/engine/prompt/schema，仍走正常队列、真实Worker与模型、写入、审计及授权下载。产物明确为验证工作文件，不进入普通合同提交页，不称正式final。由此取得发布证据而不绕过发布gate；发布后必须另跑默认正式浏览器端到端验收。自定义已解析指引同样通过该可见验证状态与通道完成资格验证，不要求用户改隐藏开关。

用户可在配置页发起自己候选指引的受控验证并查看进度、证据与失败问题；验证消耗同一授权预算。服务在政策通过后发布该私有版本；内置全局版本通过管理员/部署发布流程更新。无法验证的版本保留明确状态，不允许启用为正常任务指引，不自动替换当前可用内置版本。

P2定义机器可执行的版本验证政策，P6任何真实评分前冻结样本、标签、指标、阈值、允许边界与证据绑定。工程门禁至少：来源解析无已知漏组/未知必要条件；物理地址与结构/修订等价专项通过；适用规则有可执行正例及相关反例；登记的正常可编辑必需验证合同全部要求正确落实，qualification工作文件通过技术/业务复核、授权下载及哈希检查；无已知未授权政策、严重事实改变或必需目标漏改。这些仅为发布前证据，不是正式final交付；发布后另跑普通默认入口完整正式验收。设计内排除/不可编辑/故障用例要求正确状态，不伪装正常complete。其余质量与成本阈值由实施agent运行前说明理由并登记，不能见结果后调低。

发布服务或受控命令核对当前版本证据后事务化记录状态；证据过期或必需条件未过保持未发布。若发现来源授权实质不明确，记录具体问题并仅询问必要业务决定；不将所有新版本无条件置为released，也不以永久unreleased结束完整开发。

产品界面不让用户靠隐藏评测开关完成合同任务；暂未可用时给明确状态和可执行修复路径，不无限期提供只读半成品。开发agent必须把内置正式修改链路完成，不以动态指引验收难为理由拖延整个交付。
