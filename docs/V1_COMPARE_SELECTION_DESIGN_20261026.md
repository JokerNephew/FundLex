# V1 Compare 左右选择与选择版生成设计

日期：2026-10-26。状态：用户功能需求已确认；本文为待实施方案，不是代码已完成或已验收声明。

范围：V1 原生 Compare，关联 FL-D328（页面分层）、FL-D329（创建表单）、FL-D330（右侧差异导航）、FL-D331（左右选择与 DOCX 生成）。沿用此前先做设计的工作范围；不涉及 React V2，不部署，不调用模型。

## 1. 目标与页面边界

用户在左右合同正文旁逐处决定采用哪一侧，根据全部选择生成并下载一份新的 DOCX。原版和对比版保持不变；生成文件标注为“人工选择版”，不冒称已通过修订指引或业务合规核验。

继续采用“任务列表 → 独立创建态 → 当前任务结果 → 单组差异阅读器”的页面边界。选择版按合同组产生，多组任务内每组分别保存选择和生成版本。

阅读器主工作区是左右两份原始正文，右侧为差异选择清单；顶部为任务/合同组导航、选择进度和生成操作。比较方向仍为原版（左）→ 对比版（右），不因选择变化而交换左右文档。正文始终展示原始两侧，选择仅更新标记和选择结果预览，避免失去审查依据。

```text
返回任务结果    当前合同组                   上一组 / 下一组
已采用左侧 8 · 已采用右侧 12 · 待选择 3      [预览选择结果] [生成选择版]
┌───────────────────┬───────────────────┬────────────────────────┐
│ 原版（基准）      │ 对比版（修订）    │ 差异与选择             │
│                   │                   │ 类型 / 选择状态筛选    │
│ 原始正文          │ 原始正文          │ 第 23 处 · 修改        │
│                   │                   │ 章节位置               │
│ 差异高亮          │ 差异高亮          │ 左侧文本 / 右侧文本    │
│                   │                   │ ( )采用左侧 ( )采用右侧│
│                   │                   │ 当前选择摘要           │
└───────────────────┴───────────────────┴────────────────────────┘
```

## 2. 每条差异的选择语义

| 差异类型（以左→右为方向） | 采用左侧 | 采用右侧 |
| --- | --- | --- |
| 修改 | 保留左侧原文 | 使用右侧文本 |
| 右侧新增 | 不加入新增内容 | 加入右侧新增内容 |
| 右侧删除 | 保留左侧内容 | 删除这部分内容 |

每条状态为 `pending / left / right`，初始 `pending`。按钮或单选组使用“采用左侧（原版）”“采用右侧（对比版）”；删除差异的右侧注明“此处无文本 · 采用后删除”，新增差异的左侧注明“此处无文本 · 采用后不新增”。完整原文可展开查看，摘要不能成为唯一核对依据。

提供“全部采用左侧”“全部采用右侧”“待选择项采用左侧/右侧”和“清除此处选择”。覆盖已做选择的全量操作显示影响数量并可撤销；类型/状态筛选只改变展示，不改变选择集合，全量操作明确作用于当前合同组全部差异。生成前仍有 `pending` 时显示剩余数量，提供“下一处待选择”，不隐式替用户选择。

点击清单标题定位正文，选择控件独立于定位按钮，不把单选控件嵌入 button。当前定位状态与采用哪侧的状态分别显示，不仅依赖颜色。键盘、读屏标签和选择进度应可用。

## 3. 保存、预览与生成

选择草稿自动保存到服务端，显示“保存中/已保存/保存失败”，保存失败保留本地尚未同步选择并可重试。刷新、重开合同组恢复服务端草稿；身份切换不继承其他账号状态。保存和生成都使用乐观并发版本；冲突时保留本地选择供核对，不用旧选择直接覆盖新版本。

“预览选择结果”切换阅读器正文区域为单栏合并预览，右侧选择清单继续可用，支持返回双栏。预览按服务端同一选择快照和可执行合并计划生成，并标明选择版本；客户端可以立即展示选择摘要，但不能把 HTML 拼接结果当作 DOCX 生成已成功。尚有待选择或结构阻塞时显示对应位置/原因，不假装已有完整成稿。

生成前显示左/右/待选择数量、版式基底说明、覆盖/合并阻塞。所有项目已选择且计划可执行时，点击“生成选择版”；生成使用明确的草稿快照，处理期间重复点击不得创建重复发布。生成成功后提供：

- 人工选择版 DOCX；
- 相对左侧基底、展示实际采用右侧改动的修订痕迹 DOCX；
- 选择报告（可读报告及机器可读 JSON），记录每条选择、来源位置、源文件与差异结果哈希、选择版本、产物哈希及限制。

生成后改变选择，应显示“选择已变更，需重新生成”。历史生成版本可保留，但下载明确标识版本及与当前草稿是否一致，不能让旧按钮冒充当前选择结果。生成失败保留全部选择，并提供具体失败原因和重试入口。

## 4. 文档合并约束

建议以左侧 DOCX 为版式与包结构基底，未变内容保留左侧，采用右侧指选择差异文本。该技术约定需在页面和报告可见；选择文本不等于把右侧全部格式、页眉页脚或图片也合并。格式差异、被比较规则忽略的空白和未覆盖部件也需说明，不能承诺“全部采用右侧”就字节相等于右侧源文件。

现有 DiffItem 含左右 TextSpan、跨块 spans 和空侧 anchor；这些是展示地址。写入前需要可验证的 OOXML 编辑地址和结构计划，包括段内替换、整段插入/删除、跨段保留、表格单元格及结构关系。不能把多段文本简单连成一个 run 或换行后宣称保留了文档结构；整段删除需处理段落本身，不能只清空文本留下多余空段。

存在互相依赖或重叠的操作时，建立关联选择单元并展示联合选择原因；安全可独立执行的差异仍允许独立选择。不静默扩大某条差异的作用范围，不通过忽略操作制造生成成功。对当前不可安全合并的结构，明确定位并阻断完整选择版生成；如以后支持工作文件，须显式区分其未完成项和文件名称，不能把不完整文件作为用户已完成全部选择的成稿。

复用现有 Review 的版本校验、鉴权和产物原子发布思想；不直接复用其 `del_id` 接口，因为 Compare 输入不含引擎生成的修订标记。

## 5. 建议服务端契约

以下为待实施的契约建议，当前接口尚不存在：

- 获取选择状态：返回当前 pair 的源文件哈希、`result_sha256`、差异/选择单元清单、`selection_epoch`、逐条选择、生成能力/阻塞和历史生成信息。
- 保存选择草稿：携带期望 epoch、结果身份和差异 ID→左右选择，校验未知 ID、重复选择、关联单元约束与身份归属，原子保存并返回新 epoch。
- 预览：绑定当前草稿快照；返回可执行合并预览和具体未完成/结构阻塞。
- 生成：绑定期望 epoch、结果哈希及源文件身份；服务端读取已保存的完整选择，不信任浏览器提交的 replacement 文本；生成独立版本后原子发布成对文件及报告。
- 授权下载：按 pair、生成版本和产物种类取文件；验证归属、源文件/结果绑定及产物哈希，输出正确文件名；不能以公开 object 路径绕过鉴权。

草稿版本和生成版本分开。文件生成不修改源件、比较结果或已发布版本；过期请求不得覆盖当前草稿或挂错产物版本。

## 6. 响应式

桌面足够宽时展示双合同正文加右侧清单；按实际内容宽度决定断点，不能为了三列把合同挤到无法阅读。中等宽度支持折叠差异清单，必要时切单栏原版/对比版。手机用正文侧切换加“差异与选择”抽屉，抽屉内保留同样的左右选择和筛选；定位后切到有目标的一侧，再回到正文。选择“此处无文本”的一侧时不误显示另一侧内容已被采用。

清单和正文独立滚动；当前差异跟随、分页/虚拟滚动不能丢失离屏条目的选择。移动端生成操作和进度可从紧凑工具栏进入，抽屉应管理焦点、Escape/返回和关闭后焦点恢复。

## 7. 实施与验收

先补可写地址/选择单元及生成能力分析，再做草稿持久化、真实 DOCX 合并和产物原子发布，最后接入 V1 右侧选择清单、预览和版本下载。不能只先开放按钮而没有可用后端。

需要验证：

- 修改/新增/删除的左右选择，全部左/全部右/混合选择，重复文本、相邻差异、多段、整段和表格；
- 刷新重开、保存失败恢复、多标签冲突、跨身份清理、生成中切换合同组；
- 输入/结果/产物篡改、未知 ID、过期版本、关联单元冲突和授权下载；
- 独立重新读取实际 DOCX，核对选择目标和非目标内容、段落/表格结构、样式保留、包部件及文件哈希；接受选择修订版应与选择版一致，拒绝其修订应恢复左侧基底的对应内容；
- 390px/768px/1440px、键盘/焦点、数千条差异的清单与正文定位；
- 最终沿工作台身份入口、真实合同上传、实际 Compare Worker、选择保存、生成、结果页和授权下载验证，核对真实文件差异和报告一致性。Compare 为确定性比较/人工选择，不为本功能额外引入真实模型调用；隔离 fixture 只能作为开发验证，不替代最终交付。
