# FundLex 召回优先（C-R）改造方案（草案）

日期：2026-10-14。状态：**草案，待产品负责人确认底线后实施**。原则变更来源：产品负责人要求"可以接受多改，但不能接受漏改"。

## 1. 原则与验收口径（需运行前预登记）

- 旧原则：误改=0、漏改可接受 → 导致大量保守拒绝（实测 24 份漏改 81 处：摘要侧 40、正文变体 41）。
- 新原则：**宁多改、不漏改**；多改如实分类报告、可人工一键回退（修订痕迹）。
- 新验收口径（预登记，运行前冻结）：
  1. 目标召回：24 份标注中 137 处"应改"目标执行率 **≥95%（力争 100%）**，按动作分别报告；
  2. 多改：如实计数并分类（范围偏大/重复添加/已符合再改/复核存疑），不设上限；
  3. 零容忍：结构性破坏=0、政策文字偏离=0、产物哈希/修订等价校验失败=0。

## 2. 三层召回保证（不是"每章扫所有规则"）

1. **目录映射（模型）**：代码抽目录清单（标题+字数，几百字符，含"基金合同内容摘要"），模型输出"规则↔章节"映射；代码校验章节真实存在。
   - 实测规模：合同 24 个部分中仅 **6–7 个部分**有映射（释义、基本情况、申购与赎回、费用与税收、收益与分配、清算、摘要），其余 17 个部分直接跳过。
2. **按章盘点（模型）**：一章 + 该章相关规则子集（通常 1–9 条）一次盘点，输出强制 `{规则号, 引文, 理由}`；代码回查成唯一区间并做核心校验。
   - 调用量：规划 1 次 + 6–7 次盘点 ≈ 8 次/合同（对比暴力矩阵 24×22≈528 次）。
3. **单条补扫（兜底）**：某规则在映射章内找不到目标时，仅对**该条规则**做一次全文档补扫；仍无 → 例外清单标注"本合同确无此条款"。

## 3. 门禁翻转清单（旧 → 新）

| 现行门禁（拒绝优先） | 新行为（召回优先） |
| --- | --- |
| 整句/整段与指引旧文不一致 → 拒绝 | **扩改**：核心匹配即改；句子多了按匹配段替换、余文保留；句子少了自动扩到整句 |
| 摘要区靠别名，未配到不扫 | 摘要纳入目录映射，按普通章节扫；找不到走单条补扫 |
| 段落模板"本节已含核心" → 拒绝（U04 保护） | **取消该保护**（允许重复/覆盖，交人工在修订版取舍） |
| 复核拒绝 → 撤销动作/二轮全撤 | **降级为标记**：复核存疑照样交付，改动清单标"存疑" |
| 事实引文对不上 → 拒绝 | 一次重问；仍不对 **照改并标"证据待核"** |
| 跨动作区间冲突 → 全撤 | **固定优先级应用** + 清单标注 |
| 动作内一目标失败 → 回滚全动作 | **仅回滚失败目标**，其余保留 |
| 删除必须完整业务句，否则拒绝 | **自动扩到整句**；扩不了（跨屏障/跨段）才跳过并报告 |

## 4. 保留底线（多改的边界）

1. **政策文字逐字**：政策文案仍由代码按指引原文组装（多改可以，改错方向不行）；
2. **结构安全**：不破坏 DOCX、不越结构屏障/不可编辑区；
3. **删除不截半句**：删句自动扩到整句边界，扩不了就跳过并报告；
4. **全部可追溯**：每条改动带规则号/引文/理由/复核结论，修订痕迹可逐条接受或拒绝。

## 5. 交付形态

全量修订版（`redline.docx` + `final.docx`）+ **改动清单**（确定/存疑/已符合未改）+ **例外清单**（确无条款/结构不支持）+ 逐合同报告；评测模式产物保持"非正式合同"标记不变。

## 6. 分批实施与验收

| 批次 | 内容 | 验收 |
| --- | --- | --- |
| 1 | 摘要覆盖：目录映射 + 摘要章纳入扫描 | 摘要侧漏改 40 处显著下降；无新增结构破坏 |
| 2 | 按章盘点替换逐 action 候选 + 单条补扫 | 正文变体漏改下降；映射/补扫调用量记录 |
| 3 | 门禁翻转（扩改优先、复核降级、原子性/冲突策略） | 多改计数分类报告；零容忍项保持 0 |
| 4 | 变体转正（正文整句门槛取消）+ 全量重跑 + 重新发布 + 服务器同步 | 召回 ≥95%；发布证据重跑；服务器交付复验 2 份 |

每批流程：单测 → 全量测试（含 MySQL）→ 24 份重跑 → 对比漏改/多改 → 记录；**每批结束更新本文与实施计划**。

## 7. 预算与发布联动

- 共享账本不重置：现约 4600 HTTP / $4.6（cap 7500 / $6.0）；本改造预计 +1500 次 / +$1.0 → **运行前先登记新上限**（如 9500 / $7.5），到限即停。
- 任何 `fundlex/*.py` 变更都会使已发布包失效：全部批次完成后重跑 5+16+8 证据 → `rules/release_v2 --evidence-run` 重新发布 → 服务器同步代码与发布包并重启服务。
- 服务器（8.155.130.168）仅部署运行，不在服务器上开发。

## 8. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 多改增加人工复核量 | 改动清单分级（确定/存疑），修订痕迹可逐条接受 |
| 模型映射质量不稳 | 代码校验章节真实性 + 单条补扫 + "确无"报告 |
| 成本上升 | 按章盘点调用量与现状同量级；补扫仅对空结果规则触发 |
| 旧验收门槛作废 | 第 1 节新口径先预登记，再运行 |
