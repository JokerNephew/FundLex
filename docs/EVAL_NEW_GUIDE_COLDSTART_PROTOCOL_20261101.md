# B3 新指引冷启动协议（报审件 v1，2026-11-01，qa-feat-recall EVAL 轨）

> 目的：验证「用户上传全新指引 → 解析成规则 → 真实驱动合同修订 → 评分」全链路对**从未进过开发流程**的指引的机制级稳健性（用户原则原文：「合同修改是核心功能，不能指望通过测试结果来修复规则来提升可用性，因为用户经常会上传新的指引来解析成新的规则」）。
> **本协议先报主线审查，批准前不执行任何一步。**

## 1. 留出指引选定（≥3 份，硬隔离）

| 项 | 规定 |
| --- | --- |
| 来源 | 公开渠道真实基金公司合同修改指引（费用新规/流动性新规等同类业务指引；合同资料政策覆盖公开文本）。候选 4~6 份，主线圈定 ≥3 份 |
| 禁入名单核验 | 三查：①`git log --all` 全史文件名/内容 sha 命中=淘汰；②全树 grep 关键段落=淘汰；③任何评测/开发/测试资产引用=淘汰。核验记录入冻结清单 |
| 形态约束 | 三份须分属不同 GG 形态族（初定：条文型 ×1、表格型 ×1、勘误型「将A改为B」或附条件型 ×1），与 A2 黄金集扩充共用形态 taxonomy |
| 冻结 | 选定即 sha256 冻结入 `docs/evidence/coldstart-guides-freeze-<date>.json`（含来源 URL、获取日期、禁入核验证据）；此后**不得因解析结果更换样本** |

## 2. 流程铁律（违反即该轮作废、如实登记）

1. **全程禁人工修规则**：解析产物（规则集）一个字节不许手改——包括「微调」、条件修正、文本补全。产物差=失败如实记录，不是修规则的理由。
2. **禁回路特判**：不得针对留出指引改引擎/解析器代码后再跑（那是 A4 的职责且须用独立样本）；本协议期间代码冻结于既定 commit。
3. **代码冻结声明**：解析管线+引擎以主线裁定 commit 为准（初定 229f030 系 + 解析线当时主线版），freeze.json 记录。
4. **失败不删分母**：解析失败/结构化拒收/honest_hold 全计入结果，与成功并排呈现。

## 3. 执行步骤（每份指引独立成册）

```
S0 冻结登记（sha/来源/形态族/禁入核验）
S1 生产通道解析：上传 → 解析 → 质量门（S1-S9 检查单）→ 规则产物落盘（真实模型，账本段独立编号）
S2 A3 三层指标评分：规则召回率/结构正确率/直接可用率（对照 A2 黄金集同族形态基线；留出指引无人工 gold 时按 §4-B 口径）
S3 合同实测：选 3 份类型学已表征合同（覆盖该指引适用类型）走真实任务链路（上传→修订→下载），读实际 DOCX
S4 合同侧 S2 评分：fc=0 硬门、必改目标命中、wrong=0；若指引无对应人工标签，按「产品修订对照缺失声明+自动判定明细」如实标注
S5 成册：单指引报告（解析诊断/规则数/三层指标/合同侧结果/失败族登记引用）
```

## 4. 评分口径的双轨声明（防虚标）

- **A 轨（有 gold）**：留出指引若能获得公开人工修改对照（如同期产品修订合同对），按 A2/A3 全口径评分。
- **B 轨（无 gold）**：直接可用率只计「解析产物经质量门+金丝雀可执行、且 S3 实测产生修订产物」；召回率/结构正确率标注「无独立 gold，仅结构性自检」——**绝不把无 gold 的自检冒充有 gold 的评分**。
- 轨道判定在 S0 冻结时记录，不得事后切换。

## 5. 失败登记与去向

- 解析层失败族 → 报主线赐号入 DETAIL_APPEND_*（GG/A4 处置面）；
- 引擎层失败族 → 报主线赐号（EN1 B2/B4 处置面）；
- 协议本身缺陷（如形态族覆盖不足）→ 本文件版本化修订（变更记录段）。

## 6. 交付物清单

1. 冻结清单 JSON（sha 链）；2. ≥3 份单指引报告；3. 汇总报告（形态族×结果矩阵、与 A2 基线的同族对照）；4. 账本段（解析+合同两侧调用/费用/时长）；5. 失败族赐号申请清单。

## 7. 待主线裁决项

1. 候选指引来源清单是否批准（执行时联网取样，批准后才动）；
2. 合同选用策略：3 份/指引 是否足够，是否需含 1 份无字母类（最大不确定源）；
3. B 轨「无 gold 自检」是否满足用户「解析得好」的验收预期，或须追加人工抽查环节（抽查由主线/用户执行，不由本线自评）。
