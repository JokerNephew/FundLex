## 二、目标信息架构（IA）

### 2.1 原则
1. **一个对象一个家**：任务列表只存在一个权威页面；每页回答一个用户问题。
2. **操作就地，配置归位**：页头只放本页主操作；全局配置一律进设置域并从业务页页头撤出。
3. **用户语言，不泄底**：任何面向普通用户的文案不出现分页实现、认证模式、引擎、写入模式等技术词；运维信号进管理员视图或折叠的「系统状态」区。
4. 两套前端（V1 hash SPA / V2 React）保持同构 IA，避免双份术语。

### 2.2 页面级归属调整

| 调整 | 从 → 到 | 说明 |
| --- | --- | --- |
| A1 任务列表归并 | V1「工作台」内嵌我的任务 → 只保留「合同修改」为唯一任务列表，工作台改为**引导型主页**（最近任务 ≤5 条快捷卡 + 新建入口 + 指引状态摘要） | 消灭 P1；工作台回答「我现在该干什么」，列表页回答「我的任务都在哪」 |
| A2 「设置」按钮撤出任务页页头 | V2 `/tasks` 页头 → 删除（左侧导航已有入口） | 消灭 P2 |
| A3 设置域重组 | V1 `/settings`（实飞书绑定）→ 设置中心分两组：**账户**（密码、飞书绑定）与**系统状态**（运行能力迁移至此，且仅管理员可见）；路由名如实 | 消灭 P3/P9 |
| A4 修改指引页分区 | V1 单页五区 → 页内 tab 或锚点分区：「当前指引」「版本与对比」「规则组」，上传入口并入「版本与对比」 | 消灭 P4；项3 规则组交互提升为一级 tab |
| A5 统计卡克制化 | V2 `/tasks` 8 卡 → 保留 3~4 张高价值卡（处理中/待处理/异常 + 连接状态移出）；零值时整组折叠为一条摘要行 | 消灭 P5/P10 |
| A6 登录页可验收 | dev 模式下 `/login` 仍渲染登录页并附「以开发身份继续」入口，不再静默跳转 | 消灭 P12 |

### 2.3 导航结构（目标态）

- V1：工作台（引导主页）/ 合同修改（唯一任务列表）/ 合同比对 / 指引生成 / 修改指引（tab 化）/ 模型配置 / 设置（账户+系统状态）— 飞书绑定并入设置。
- V2：/tasks（列表，页头仅「新建任务」）/ /tasks/new / /compare / /guides / /models / /settings（账户+系统状态）— 保持现有路由，仅内容与页头调整。

## 三、设计语言巩固（token 复用与补全）

沿用既有色系与品牌调性**不变**；在已验收的 token 体系上补全缺口。

### 3.1 已有资产（复用，不新造）
- **字号阶梯** `--text-xs/sm/base/lg/xl/2xl`（FL-D731 收口，列表口音已豁免）。
- **列表 token** `--list-header-bg/color`、`--list-cell-x/y`、`--list-row-border`（项4 统一成果，V1/V2 共用语义）。
- **状态徽标/药丸**（已发布/内置/当前使用等 pill）、**卡片 + page-heading** 模式、ErrorState/Spinner（V2 ui）。
- **工具类** `u-mt-4` 等间距工具（V1）。

### 3.2 需补全的 token / 组件
| 缺口 | 方案 |
| --- | --- |
| 统计卡无统一规格 | 新增 `--stat-value-size`、`--stat-label-color`，定义 StatCard 模式（值/标签/副注三层），V2 落地后回灌 V1 |
| 空态无组件 | 定义 EmptyState 规格：图标槽 + 一句状态 + 一个主动作链接；分页/列表/面板共用，文案句式统一（消灭 P6/P7 的句式分裂） |
| 加载态不一致 | 统一骨架/Spinner 适用规则：列表骨架行、卡片区 Spinner、按钮内 spinner；写进规格而非逐页临场发挥 |
| Tab 组件只在 guide-diff 局部 | 提升 `.guide-diff-tabs` 模式为通用 Tabs 规格（供 A4 指引页分区复用） |
| 技术信息区无容器 | 定义「系统状态」折叠区模式（管理员可见、默认收起、键值人读化）供 A3 复用 |
| 按钮宽度失控（P11） | 按钮规格补「主操作不随容器全宽，max-width 内容自适应」规则并全局排查 |

### 3.3 不做什么
- 不改主色/强调色/底色；不引入新字体族；不动已豁免的列表排版口音。

## 增补节（2026-11-01 第三轮）：合同修改结果页信息架构重构方案（FL-D818）

> 用户原话："各种字密密麻麻堆在一起很不直观也很不方便看，好好想想怎么优化，而不是只是在原来的基础上进行微调"。允许推翻现有 DOM 结构。本节为**方案**（线框+理由），施工随批4，证据按末批验收闸。

### 0. 结果页要回答的问题（设计出发点，顺序即动线）

1. **我的合同改了什么？**（当前埋在三屏外的逐条 `<details>` 折叠里——V1 app.js:944 clauseRow 每处一折叠；V2 DocumentDetailPage:100-120 targets 全默认闭合）
2. **还有哪些没改完、要人工核？**（当前分散三处：概览数字 + 异常点折叠 + 徽章；V1 还有「仍需人工核对」与「未自动修改的条款」两个同义区块并列 app.js:932/1180）
3. **产物在哪？**（当前被拆两半：主下载区只有 docx；报告 MD/JSON 与评测产物藏进「高级详情」折叠——V1 app.js:1194、V2 DocumentDetailPage:153）
4. **怎么下载？**（10 种 kind 按钮高密度平铺+长标签换行，无目的分组）

现状致命伤：**核心问题（①②）的答案被折叠，技术细节（SHA/version_id/诊断来源/error_code/8 阶段轨道）占据同屏视觉权重**——恰好与用户三禁令相反。

### 1. 目标信息架构（四层动线，V1/V2 同构）

```
┌─ L0 结论带（一屏一眼）────────────────────────────────┐
│ [合同名]                        [状态徽标]              │
│ 改完 N 处 · 还有 M 处要人工核    [下载最终合同](主按钮) │
│                                  [逐条审阅修改]→review │
├─ L1 核心工作区（双栏，平铺不折叠）──────────────────────┤
│ 改了什么 N 处              │ 还要人工核 M 处            │
│ ├ 条款名·一句改了什么·徽标 │ ├ 条款名·为什么没改·原文摘录│
│ ├ …（每条点开看前后对照）  │ ├ …（指引要求并入条目正文） │
├─ L2 产物区（按目的三分组）─────────────────────────────┤
│ 最终用的合同: [最终版][选择版]                          │
│ 对照与审阅:   [带修改标记版] →逐条审阅                  │
│ 报告与数据:   [文本报告][原始数据(JSON)]                │
├─ L3 依据区（降权，仅异常合同展开）──────────────────────┤
│ 为什么判定可处理：一段人话（+引文）                     │
└────────────────────────────────────────────────────────┘
```

### 2. 逐区裁决与理由

| 区 | 现区块（V1 / V2） | 处置 | 理由 |
| --- | --- | --- | --- |
| L0 结论带 | V1 `.result-summary`(app.js:1172-74) / V2 header+「交付概览」6 字段 dl(:169,:86-92) | 收敛为一句结构话结论「改完 N · 待核 M」+单徽章；V2 交付概览 6 字段 dl 并入 | 三徽章/六字段与明细行重复表达（V1 表4①、V2 表4） |
| L1 左「改了什么」 | V1 clauseRow `<details>`(app.js:944) / V2 targets details(:100-120) | **平铺列表**：每行=条款名+一句改了什么+状态徽标；前后对照点开即看（行内展开，不是整页折叠跳转） | 核心问题的答案必须在首屏可视；V2 审计"必须升层"项 |
| L1 右「人工核」 | V1 「仍需人工核对」+「未自动修改的条款」双区块(app.js:932/1180) / V2 异常点折叠(:122-128) | 合并为**单一来源**；「查看指引要求」「诊断来源」「内部编号」三折叠删，指引要求并入条目正文 | 双区块语义重合（V1 表1）；诊断来源是管线名词（V2 表1） |
| L2 产物区 | V1 结果文件 grid+「高级详情」折叠(app.js:1188-95) / V2 交付文件+高级详情(:144-154) | 按用户目的**三分组**；报告 MD/JSON 从折叠解救为普通下载行；删 SHA-256/version_id；按钮长标签改短名（下载物词典统一，见批3文案清单「最终版/选择版/带修改标记」） | 「产物在哪」当前被砍成两半（V2 发现#3） |
| L3 依据区 | V1 「处理依据与详细状态」大折叠(app.js:1185，二级嵌套) / V2 「业务依据」卡(:181-185) | 大折叠整体拆废：资格依据人话一段常态可见（仅 ineligible/diagnosed 时显示）；上传状态/目录状态等系统视角 dl 删（无用户行动语义） | 典型"塞进折叠栏充数"（V1 表4⑧） |
| 删 | 技术字段全扫：原件 SHA-256、指引版本 version_id、阶段轨道、原始 error_code、rule_id 行首、租约心跳/落库 | 删（排障去服务端日志）；rule_id→规则标题 | 内部口径外露成片（V1 发现#4、V2 发现#4） |
