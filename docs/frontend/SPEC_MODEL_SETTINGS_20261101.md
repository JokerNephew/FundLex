# 模型配置页重做规格（2026-11-01，项 1 / FL-D732）

> 用户要求：**不要想着在原基础上微调**，参考其他页面或优秀 skill 的优化。本规格是 V1（app.js `renderModelSettings`/compare.html `#view-models`）与 V2（`src/pages/Settings/ModelSettings.tsx`）的共同实施单，前端主线（l8yCbACU）设计，V1 worker（ivRkf1jH）与 V2 worker（81FirpsQ）同图施工，前端主线验收一致性。

## 一、设计方向（品质目标）

- 第一眼回答三个问题：**现在改合同用的是哪个模型？检查用的是哪个？验证过没有？** 不先看到表单。
- 从「填表单」改为「状态卡 → 需要时才编辑」：默认读取态、点击「修改配置」才进入编辑态；编辑态有明确的保存/取消，不再一整页两个长表单堆。
- 与全站共享 token/卡片/徽标/按钮体系；不在本页发明新视觉。
- 用户视角原则：成本/隐私提示保留显式句（FL-D723 同款文案），配置错误不出现技术字段名。

## 四、状态与交互细则

- **默认读取态**：进入页面只要不是「第一次见到配置错误/保存后」，一律显示读取态；读取态不显示任何 input/select。
- **编辑态**：只影响本卡；另一张卡照常显示读取态；编辑时可点「取消」无脏检查直接回读取态。
- **保存**：两版都保持现有 API 契约（一次提交两角色完整 preferences）；「保存」按钮按下时校验必填；成功后回到读取态并刷新概要；**不改 `model_settings` 后端端点**。
- **验证连接**：仅当前编辑的卡有效；结果写在卡内 `role="status"`；已保存的密钥留空=保留原密钥的语义保持不变。
- **徽标逻辑**（两版一致）：
  - source==='system' → 「系统默认」(muted/success 系 soft，建议 `--surface-subtle` 底 muted 字，因为这不是需要行动的状态)。
  - source==='personal'：未验证 →「自定义·未验证」(warning soft)；已验证（本次会话验证过或后端有验证记录）→「自定义·已验证」(success soft)。若后端无验证时间字段则仅显示「已验证」不造时间。
- **V1 anchor 保留**：`#model-settings-card`、`#model-settings-body`、`#model-settings-source`、`data-action="model-settings-save"|"model-settings-reset"|"model-copy-primary"`、可聚焦元素；新增控件 id 须新增不能复用旧 id 派驻新语义。
- **V2 anchor 保留**：`「模型配置」heading`、`「验证连接」按钮文本`、`role="status"`、FormField 可访问名。

## 五、技术约束

- 沿用统一 token（字号/间距/圆角/按钮/徽标），卡片样式即项目统一的 `.card card-pad` ≈ `.ui-card`；本页不新增视觉 token。
- 表单网格：每卡 `form-grid`（label 12px muted 在上，控件在下；整行两列、窄屏一列），控件宽度 100%；不为本页设独立字体。
- 编辑态表单回填：读取最近 preferences 直接回填，不要求用户重新选 provider。
- 错误：`role="alert"`；不出现 connection_id/legacy_model/system_model 字段名。
- 不引入新库、不动后端、不改下载/其它页。
