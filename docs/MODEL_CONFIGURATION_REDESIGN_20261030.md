# 面向普通用户的模型配置重设计与实施状态（2026-10-30）

## 用户纠正

用户需要配置自己的供应商、模型与API Key，不是调整超时/输出token/重试/上下文字符或编写JSON。
检查模型和执行模型必须可分别配置。此前实现将供应商和Key锁为系统配置、默认隐藏复核设置，偏离需求。
独立页面入口保留。BYOK已按生产发布基线移植并部署；实际生产前端当前仍默认V1。

## 页面结构

页面标题“模型配置”，说明“选择负责修改合同的模型，以及负责检查修改结果的模型”。
始终显示两张卡片，不再默认勾选继承从而隐藏第二个角色：

1. **执行模型**：理解合同、定位条款、生成修改方案与修改内容。软件负责实际DOCX写入。
2. **检查模型**：核验修改结果、检查遗漏和问题。说明检查流程独立，不承诺同模型时具有不同模型的独立性。

每张卡片分别选择“使用系统默认”或“使用自己的模型”。自有模型只显示：

- 供应商：下拉选择 OpenAI Chat Completions 兼容入口；不把兼容协议冒充原生供应商适配。
- API Key（界面称“访问密钥”并说明由供应商控制台获取）：密码输入，已保存时显示“已保存”，
  可替换/删除，不回传原值、不用掩码占位值覆盖真实Key。
- 模型：展示常用名称建议并允许手填；目前未请求供应商模型目录，建议名称不保证账号/地区可用。
- 服务地址：已适配供应商自动填好且不要求用户理解；只有“其他兼容服务”需要填写，附直白说明和格式示例。
- “验证连接”按钮及成功/失败状态，分别验证两个角色。

两卡始终可见，可不同供应商、不同Key、不同模型；提供“复制执行模型配置”便捷动作，但必须用户主动选择，
之后仍分别展示和可编辑。无默认隐藏的“继承主模型”。页面底部“保存配置”和“恢复系统默认”。
恢复默认需确认，不删除运行中任务所需的历史凭据版本；页面标明仅影响本人新任务。

删除所有面向用户的timeout/token/retries/context/JSON输入，而不是简单折叠为高级选项。
系统按供应商与模型能力管理这些技术参数；不让用户依赖参数调整保证基本可用。

## 交互与安全实现

- 错误使用业务语言：密钥无效、账户余额不足、模型不可用、地址无法连接、服务暂时繁忙；
  不展示含密钥/请求头/内部路径的原始供应商错误。不能把“保存成功”写成“连接验证成功”。
- 连接测试是用户明确触发的真实请求，可能产生少量费用，给出简短说明；不提交合同文本。
  当前真实调用暂停保持，未经恢复授权不由agent自动测试。模型列表/最小响应测试与实际任务能力区别标记。
- 已实现owner隔离的供应商连接：Fernet加密保存，主密钥通过部署变量
  `FUNDLEX_MODEL_SECRETS_KEY`注入；API/任务快照/报告不返回密钥，Worker按不可变连接版本引用解密。
  生产已配置此变量并完成Fernet往返检查；0600配置备份为
  `/var/backups/fundlex/fundlex-recall-env-with-byok-key-20261030-225108`，独立主密钥备份位于
  `/var/backups/fundlex/fundlex-model-secrets-key-20261030-224747/FUNDLEX_MODEL_SECRETS_KEY.env`（父目录0700、文件0600）。
- 用户自填服务地址只能携带该用户为该连接提供的Key，绝不携带系统共享Key或任意服务器环境变量。
  限制公网HTTPS出口、内网/回环/链路本地/云元数据地址及重定向/DNS重绑定；不是开放任意服务器请求代理。
- 两个角色已接入primary/review真实路由：V2任务固定primary为执行、review为检查；两者可独立选择个人连接或对应角色的系统默认端点配置。
- 现有个人技术参数偏好迁移为可识别的配置，不丢失用户数据；未经连接验证的旧模型名不能冒称可用。
- 供应商支持范围以真实适配和验证为准，不能仅新增供应商名称下拉就宣称支持。

## 验收建议

普通用户无需JSON/终端即可设置两个不同模型并看懂状态；跨用户隔离、密钥不回显/不入日志、
错误提示、保存回读、默认恢复、任务快照/凭据轮换、出口安全均需测试。
恢复真实调用授权后，使用不同执行/检查模型完成正式合同路径，核对Worker实际角色和下载产物；
不能以页面分离或连接测试代替最终合同交付验收。
