# FundLex 召回优先版（C-R）目标设计

日期：2026-10-14。状态：**目标设计**（描述改造完成后的系统形态，不含实施步骤）。原则来源：产品负责人要求"可以接受多改，但不能接受漏改"。

## 1. 一句话

合同进来 → 按指引**尽量全改** → 输出"全量修订版 + 分级改动清单 + 例外清单"；政策文字逐字、结构安全、全部可追溯、可逐条回退。

## 2. 设计原则

1. **召回优先**：映射、盘点、补扫三层保证"应改尽改"；
2. **多改可接受**：范围偏大、重复添加、对"已符合"的再编辑都允许，但必须**如实标记**，人工在修订版上取舍；
3. **四条底线**：政策文字逐字（代码组装）、结构安全、删除不截半句、全部可追溯可回退。

## 3. 系统由七个部件组成

```
① 预检与画像      【代码为主】结构预检、资格判定、收费画像（模型抽事实 + 代码独立比对）
② 目录映射        【模型】代码给目录清单+规则索引 → 模型输出"规则↔章节"映射 → 代码校验
③ 按章盘点        【模型】一章 + 该章相关规则子集 → {规则号, 引文, 理由} → 代码回查区间
④ 单条补扫        【模型】某规则在映射章空结果 → 仅对该规则做一次全文档补扫
⑤ 扩改与生成      【代码+模型】区间准备（整句扩展/余文保留/冲突优先级）+ 文字生成
⑥ 复核            【模型+代码】独立模型逐要求复核 + 实际产物复核；结论=标记，不回撤
⑦ 交付与发布      【代码】修订版 + 改动清单 + 例外清单 + 报告；发布指纹绑定
```

## 4. 主流程

```
合同 DOCX
   │
   ▼
① 结构预检 / 资格判定 / 收费画像
   │   （非普通类型基金：整份排除，不出修订版）
   ▼
② 目录映射（含"基金合同内容摘要"章）
   │   · 代码抽目录（标题+字数）＋规则索引 → 模型映射 → 代码校验章节真实存在
   │   · 实测：24 个部分只有 6–7 个部分有映射，其余直接跳过
   ▼
③ 按章盘点（一章 + 相关规则子集，通常 1–9 条）
   │   · 输出强制 {规则号, 引文, 理由}
   │   · 代码回查：引文唯一 → 精确区间；核心词校验；区间可写
   ▼
④ 空结果补扫（仅对"映射章内找不到"的单条规则）
   │   · 该规则全文档补扫一次 → 仍无 → 例外清单标"本合同确无此条款"
   ▼
⑤ 扩改与生成
   │   · 句子多了 → 按匹配段替换，余文逐字保留
   │   · 句子少了/半句 → 自动扩到整句边界
   │   · 区间冲突 → 固定优先级应用 + 标记
   │   · 政策文案 → 代码按指引原文组装（类别槽位按实际类别实例化）
   │   · R01/R02/R10 → 模型草稿 + 引文/事实核验（核验不过：照改 + 标"证据待核"）
   ▼
⑥ 复核
   │   · 独立模型逐要求复核 + 实际产物复核（要求/保留/覆盖）
   │   · 结论只做标记：确定 / 存疑 / 证据待核（不再撤销改动）
   │   · 仅结构性错误（区间不可写、产物哈希/修订等价失败）才回滚该条
   ▼
⑦ 交付
       · redline.docx（修订痕迹，可逐条接受/拒绝）
       · final.docx（接受修订后）
       · 改动清单：确定 / 存疑 / 证据待核 / 已符合未改
       · 例外清单：确无此条款 / 结构不支持（跨段、表格、文本框…）
       · 报告 + 发布指纹（引擎/模型传输绑定；未发布包只出评测版）
```

## 5. 数据形态

| 数据 | 形态 |
| --- | --- |
| 规则（指引的编码） | 规则 JSON：规则号、章节/语义、定位（旧文/业务词）、生成方式、检查项、来源哈希（不变） |
| 盘点输出 | `{规则号, 引文, 理由}`（模型），代码回查成字符区间 |
| 改动记录 | 规则号、区间、原文、新文、来源（政策原文/模型草稿）、复核结论、标记 |
| 改动清单 | 确定 / 存疑 / 证据待核 / 已符合未改（分类计数） |
| 例外清单 | 确无此条款 / 结构不支持（逐条原因） |

## 6. 用户看到的标记体系

| 标记 | 含义 | 处理建议 |
| --- | --- | --- |
| 确定 | 有定位引文、内容检查与复核均通过 | 直接接受修订 |
| 存疑 | 已改，但复核有疑问 | 人工看一眼修订 |
| 证据待核 | 已改，但模型给的事实引文无法回查 | 人工核对政策文字 |
| 已符合未改 | 原文已满足指引，未改动 | 抽查即可 |
| 确无此条款 | 全文档补扫后确认合同无对应条款 | 无需处理 |
| 结构不支持 | 跨段/表格/文本框等无法安全编辑 | 人工处理 |

## 7. 章节映射规模（实测口径）

- 合同 24 个部分 → 通常 **6–7 个部分**有映射（释义、基本情况、申购与赎回、费用与税收、收益与分配、清算、摘要）；
- 每章映射 1–9 条规则；盘点调用量 ≈ **8 次/合同**（规划 1 次 + 每章 1 次），不是"每章 × 22 条"；
- "不漏"的保证 = 映射（模型认章节）+ 单条补扫（空结果规则）+ "确无"报告，而不是暴力全扫。

## 8. 验收口径（目标状态的质量标准）

1. 目标召回：24 份标注中 137 处"应改"目标执行率 **≥95%（力争 100%）**；
2. 多改：如实分类计数（范围偏大/重复添加/已符合再改/复核存疑），不设上限；
3. 零容忍：结构性破坏=0、政策文字偏离=0、产物哈希/修订等价失败=0。

## 9. 明确边界（仍然拒绝或不做的）

- 结构屏障：合并表格、文本框、内容控件、目录域等不可编辑区域不碰；
- 跨段删除且无法扩成整句：跳过并报告（不截半句）；
- 非普通类型基金（ETF、货币、同业存单等）：整份排除；
- 引文无法回查（幻觉）或区间不唯一：该条拒绝，进例外清单；
- 规则包未发布：只出评测版（带"评测"标记），不产生正式合同。

## 10. 与现行版本的区别

| 维度 | 现行版本 | C-R 目标设计 |
| --- | --- | --- |
| 定位 | 代码候选段 + 单条规则切片；摘要靠别名 | 目录映射 + 按章盘点 + 单条补扫（含摘要） |
| 句/段一致性 | 与指引旧文不一致即拒 | 扩改：核心匹配即改、整句扩展、余文保留 |
| 复核作用 | 拒绝即撤销 | 结论只做标记（存疑/证据待核），结构性错误才回滚 |
| 冲突/原子性 | 冲突全撤、一失败全回滚 | 优先级应用 + 仅回滚失败目标 |
| 交付物 | 修订版 + 例外清单 | 修订版 + **分级改动清单** + 例外清单 |
| 质量取向 | 误改=0、漏改可接受 | **宁多改、不漏改**（多改可报告、可回退） |
