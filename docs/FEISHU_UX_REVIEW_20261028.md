# 飞书入口产品与用户体验复核（2026-10-28）

## 1. 结论

飞书入口的核心问题不是某一个按钮，而是**首步设计把“填任务名”放在“发合同”之前**。用户来飞书是为了“发合同 → 拿结果”，任务名是低价值、可自动生成的信息；把它做成必经表单，既增加一步操作，也把整个任务卡在飞书最容易出问题的表单提交回调上。用户看到的“卡片闪一下就没”，是表单重绘、旧卡原地更新和缺少下一步稳定卡片共同造成的。

本轮按“文件优先、单活卡、每步有下一步”的原则重构，并将真实生产任务暴露的“合同带修订痕迹 → 任务 completed 但无交付文件 → 卡片仍绿色”问题一并修复。

## 2. 关键发现（按优先级）

| 优先级 | 发现 | 用户影响 | 处理 |
| --- | --- | --- | --- |
| P0 | 任务名称表单是文件收集的必经门槛 | 保存失败/卡片重绘时任务完全无法继续；多一步操作 | 改为文件优先；任务按时间命名，取消命名入口（FL-D417/428） |
| P0 | 点击任务/保存后只更新旧卡 | 用户只看到 toast，误以为没有下一步 | 状态转换发新卡；旧卡 patch 为失效卡（FL-D415/418） |
| P0 | 合同带修订痕迹时任务 completed 但 not_generated | 用户以为成功，实际没有最终版/修订版 | 上传前预检修订痕迹并拒绝；结果卡橙色说明原因（FL-D425/426） |
| P1 | 取消草稿后只发“已取消”文本 | 用户在当前消息流看不到入口，无法开始新任务 | 取消后重发任务中心卡并更新 Pin（FL-D427） |
| P1 | 置顶任务中心依赖人工 Pin | 新用户/换卡后没有常驻入口 | 绑定后自动 Pin；state 持久化；草稿变化刷新置顶卡（FL-D420） |
| P1 | 卡片回调同步执行重操作 | 多文件确认/发送结果可能超过飞书 3 秒 | 回调线程池 + 2 秒等待 + “已开始处理” toast（FL-D421） |
| P1 | “我的任务”下一页无效 | 任务多时找不到历史任务 | 真实分页，6 条/页，上一页/下一页（FL-D419） |
| P1 | 状态/错误/大小直接显示英文码和 bytes | 用户不知道发生了什么、该做什么 | 中文状态/阶段/错误/大小映射；每卡加“下一步”（FL-D422） |
| P2 | 指引“发送草案/证据”忽略 kind；无“发送全部” | 发错文件或重复点击 | 按 kind 发送；结果卡“发送全部交付”（FL-D423） |
| P2 | 对比卡首句要求先去工作台 | 与“飞书内办理”目标冲突 | 改为第 1/2 步直接发左右 DOCX（FL-D424） |

## 3. 目标流程

### 合同修订 / 诊断 / 评测

1. 从置顶任务中心点任务；
2. 卡片直接提示“发送 DOCX”，任务名显示为创建时间；
3. 第一份文件到达后，新卡片出现在会话底部，显示文件、大小、移除和“确认创建任务”；
4. 不提供命名/改名入口，任务名固定为创建时间；
5. 确认后输入卡失效，状态卡成为唯一活卡；
6. 状态卡更新进度/中文状态，完成卡提供“发送全部交付”或“发送报告”；
7. 取消草稿后自动重发任务中心卡并更新 Pin，可直接开始新任务。

### 合同对比

1. 点“合同对比”；
2. 第 1 步发左侧原版；
3. 第 2 步发右侧对比版；
4. 可交换/替换；
5. 确认后状态卡显示差异数和对比页深链。

### 指引

1. 点“生成指引”；
2. 直接发法规 PDF/DOCX；
3. 确认卡显示文件名/大小；
4. 完成后发送草案/证据，审核和发布仍在工作台。

## 4. 设计原则（后续改动遵守）

- **文件优先**：先让用户完成高价值动作，名称、分类等元数据尽量自动推导。
- **单活卡**：同一草稿/任务只保留一张可操作卡；旧卡必须失效，不能留下可点击的错误状态。
- **每卡有下一步**：状态、失败、部分完成都必须说明“现在该怎么办”，不能只给状态码。
- **不伪装能力**：飞书卡片没有文件上传组件，文件只能走消息；不在卡片里做“假上传”。
- **失败前置**：能在上传时判断的失败（格式、修订痕迹、受保护、超限）不要留到任务结束。
- **深链兜底**：飞书不能完成的逐处选择、指引审核/发布，给明确工作台深链，不要求用户自己找。

## 5. 仍需验证

- 真实用户从置顶卡点击 → 发送**无修订痕迹**的 DOCX → 确认 → Worker 真实处理 → 最终版/修订版/报告回传，完整走通一次。
- 多文件（≥5）确认，观察卡片回调是否还会出现“操作超时”。
- 带修订痕迹、受保护、超限、PDF 四种错误文件的上传提示。
- 指引/诊断/评测的真实 model run（预算未授权）。
- Web 端对 `EXISTING_REVISION_UNSUPPORTED` 的中文展示。

## 6. 观察指标

- 任务卡点击 → 首份文件到达的转化率；
- 首份文件 → 确认创建任务的转化率；
- 确认后任务创建失败率（按错误码）；
- 状态卡发送失败/outbox 重试次数；
- not_generated / incomplete 任务占比及原因分布；
- 用户重复发“菜单”、重复点击确认、发送“？”/“怎么用”的次数。
